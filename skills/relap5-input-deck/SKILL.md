# RELAP5 Input Deck

Use the bundled parser rather than ad hoc text replacement. It understands RELAP5 card identifiers, continuation records, comments, quotes, and replacement/deletion semantics.

## Workflow

1. Parse the deck first. Confirm the title, effective-card count, warnings, and the relevant final cards:
   ```powershell
   python scripts/relap5_inp.py parse PATH --json
   ```
2. Locate the exact field on the **effective** card. Use a short AND query against card number, keyword, or current value:
   ```powershell
   python scripts/relap5_inp.py search PATH "100 new"
   ```
   Copy the returned target. Its form is `CARD:KEYWORD:FIELD@SOURCE_LINE`. `FIELD` is one-based; `SOURCE_LINE` is the physical line where the logical card starts. Pure numeric cards use `-` as the keyword.
3. Preview an edit before changing a shared or important deck:
   ```powershell
   python scripts/relap5_inp.py modify PATH --target 100:new:2@5 --value transnt --expected stdy-st
   ```
   Without `--apply`, this is dry-run and must not change the file.
4. Apply only after the preview matches intent:
   ```powershell
   python scripts/relap5_inp.py modify PATH --target 100:new:2@5 --value transnt --expected stdy-st --apply
   ```
5. Re-parse after a real edit and report the changed line plus any warnings. Do not silently edit a different occurrence to work around a failed locator.

## Prisma modify_inp

Prisma accepts the same target and value:

```text
ACTION       OBJECT       PARAMETER 1          PARAMETER 2
modify_inp   input.txt    100:new:2@5          transnt
```

`KeyPrisma.modify_inp()` writes immediately; it has no CLI dry-run flag. Supply the exact locator generated by `search`, and keep `object` as the deck filename relative to the case run directory. For a scripted bulk workflow, preview the target with the CLI first and apply one field at a time. See [references/modify-inp.md](references/modify-inp.md) for failure handling and verifiable examples.

## Guardrails

- Edit only a final effective card. Repeated card numbers replace earlier data; a card number with no data deletes the earlier card.
- Never infer a field target from column position or from the first field when the card has a text keyword. Use the parser's target.
- Keep quoted fields quoted and numeric fields numeric. Do not append a missing field, insert a new card, or rewrite comments to make an edit succeed.
- Preserve an existing encoding/BOM and newline style. The parser writes atomically and re-parses the candidate; a failed verification means no write.
- A blank line or comment between a data card and `+` makes the continuation invalid.
- Only the first 80 columns are data. Do not put meaningful content after column 80.
- Do not run `relap5.exe` as part of parsing or modification. Running the solver is a separate action requiring explicit intent.

For card syntax, field forms, deletion rules, continuation behavior, and card-family routing, read [references/relap5-card-guide.md](references/relap5-card-guide.md). For target resolution, dry-run, verification, and Prisma integration details, read [references/modify-inp.md](references/modify-inp.md).
