# 测试用例表格填写规范

## 1. 基本结构

1. 文件可包含多个 sheet，其中名称为 `testcase`（不区分大小写）的页面会被框架读取。
2. `testcase` 页第一行是表头，表头不允许出现跨多行的合并单元格。
3. 数据行必须连续填写，中间不能有空行。
4. 同一用例的多个步骤，第一列（测试用例编号）使用 N 行 × 1 列的合并单元格。
5. 固定列含义：

| 列 | 含义 | 是否作为步骤字段 |
|---|---|---|
| A | 测试用例编号 | 否 |
| B | 运行目录 | 是 |
| C | `action`（关键词） | 是 |
| D | `object` | 是 |
| E-H | 各关键词所需的参数 1 至参数 4 | 按关键词使用 |

代码内部把 B-H 作为 7 个数据单元格，索引依次为 `0..6`。不同关键词使用的列不同，不要机械地填满所有参数。

## 2. 按关键词填写字段

| 关键词 | 运行目录 | `object` | 参数 1 | 参数 2 | 参数 3 | 参数 4 |
|---|---|---|---|---|---|---|
| `folder_prep` | 新建运行目录 | 运行标识 | 源输入卡 | 可执行程序 | 附加依赖（可选） | - |
| `modify_inp` | 运行目录 | 输入卡文件名 | **变量定位** | **新值（修改后）** | - | - |
| `run` | 运行目录 | 可执行程序 | 输出文件名 | 结果关键字 | 模拟值 | - |
| `run_relap5` | 运行目录 | `relap5.exe` | 输入卡名 | 输出文件名 | 超时（秒） | - |
| `run_software` | 运行目录 | 可执行程序 | 软件类型 | 输入卡名 | 输出文件名 | 超时（秒） |
| `check_output` | 运行目录 | 输出文件名 | 结果关键字 | 期望值 | 软件类型（可留空） | - |
| `run_code` | 运行目录 | 可执行程序 | 命令行参数 | - | - | - |
| `check` | 运行目录 | 检查对象 | 说明 | - | - | - |

- 未使用的参数列应留空。`run` 只用于普通被测程序；RELAP5 推荐使用 `run_software`（也可继续使用旧关键词 `run_relap5`），不要用 `run` 执行 `relap5.exe`。
- `run_software` 的“软件类型”推荐填写下表中的标准键，也接受常见别名（如 `RELAP5`、`NUSOL-SYSLMR`、`nusolsyslmr.exe`、`中子物理软件`）。
- `check_output` 的“软件类型”可留空；留空时按 RELAP5 解析，以兼容旧剧本。若输出中包含 `key: value` 行，则优先使用该通用格式。
- `folder_prep` 会把源输入卡复制为运行目录下固定的 `input.txt`，因此后续 `modify_inp` 的 `object` 通常填写 `input.txt`。可执行程序仅复制有效的 Windows PE 文件；0 字节或非 PE 的占位 exe 会被忽略。
- `folder_prep` 默认整体复制软件库中该软件的 `bin/`。参数 3（B-H 中的第 6 个数据单元格，Excel G 列）用于覆盖附加依赖：留空时复制 `bin/` 和软件登记的默认运行依赖；未登记默认依赖时仍保留旧版自动复制 `tpf*` 物性文件的行为。
- 参数 3 填 `全部` / `all` 时复制软件库 `bin/` 和软件登记的全部默认运行依赖；填 `无` / `none` / `不复制` 时不复制 `bin/`、默认依赖或旧版 `tpf*` 文件。
- 参数 3 也可以填写一个或多个相对路径 / glob，例如 `runtime/*.dll` 或 `runtime/*.dll, properties/tpfh2o`。显式填写后只复制匹配的文件，不再使用默认依赖。
- 依赖按软件库 `bin/`、可执行程序目录、项目 `inputs/`、项目 `inputs/<软件标识>/` 的顺序查找；项目文件会覆盖软件库同名文件，并保留相对子目录。绝对路径、盘符和 `..` 会被拒绝；文件缺失只记录 warning，不会中断 `folder_prep`。
- 多输入卡软件（如“主输入卡 + 数据表”）在软件库登记多张输入卡后，`folder_prep` 除 `input.txt` 外还会把每张输入卡按**原文件名**一并复制到运行目录；`run_software` 的“输入卡名”填写主输入卡即可，其余输入卡由软件定义自动带入。
- 输入卡文件可使用 RELAP5 固定列、自由格式、8 位卡号、小编辑卡、外部列表行号、续行和注释等格式。输入卡页可直接选择文件或粘贴内容解析。

### 多软件适配状态

| 软件类型 | 状态 | 说明 |
|---|---|---|
| `relap5` | 可用 | RELAP5 热工水力系统分析程序 |
| `nusolsyslmr` | 可用 | NUSOL-SYSLMR；输入/输出与 RELAP5 一致，复用 RELAP5 运行和解析逻辑 |
| `neutron_physics` | 预留，尚未实现 | 中子物理/反应堆物理软件；当前执行会明确失败 |
| `subchannel` | 预留，尚未实现 | 子通道热工水力软件；当前执行会明确失败 |
| `fuel_performance` | 预留，尚未实现 | 燃料性能分析软件；当前执行会明确失败 |

预留适配器不会启动求解器、创建输出文件或伪造测试结果。使用预留类型时，`run_software` 步骤会失败并提示“适配器已预留但尚未实现”；联调前必须先完成该软件的适配器实现。

### `run_software` 填写示例

RELAP5：

```text
编号              运行目录          action        object       参数1    参数2       参数3   参数4
TC-RELAP-MINI     RELAP-MINI-001    folder_prep   TC-RELAP-MINI relap5\mini.i relap5\relap5.exe
                  RELAP-MINI-001    run_software  relap5.exe   relap5   input.txt   outdta  600
                  RELAP-MINI-001    check_output  outdta       p@100010000 1.00000E+05 relap5
```

NUSOL-SYSLMR（输入/输出与 RELAP5 一致，资源位于 `inputs/nusolsyslmr/`）：

```text
编号              运行目录          action        object                参数1                    参数2                       参数3     参数4
TC-NUSOL-LMR      NUSOL-LMR-001     folder_prep   TC-NUSOL-LMR          nusolsyslmr\indta.i      nusolsyslmr\nusolsyslmr.exe
                  NUSOL-LMR-001     run_software  nusolsyslmr.exe       nusolsyslmr              input.txt                   outdta    600
```

结果检查继续使用 RELAP5 的 `p@控制体编号`、`tempf@控制体编号` 语法或带一个捕获组的正则；
期望值必须来自当前算例，不能把其他输入卡的示例值套到 `indta.i` 上。NUSOL-SYSLMR 使用配套的
`tpfbipb` 和 `tpfh2o`；运行前会先复制公共物性文件，再由 `inputs/nusolsyslmr/` 中的专用文件覆盖。

预留的中子物理软件（当前预期失败）：

```text
TC-NP-001  NP-001  run_software  solver.exe  neutron_physics  input.inp  output.txt  600
```

预留软件接入新求解器时，在 `software/` 下实现适配器并注册到 `software/registry.py`，不要修改 B-H 固定列布局。

## 3. `modify_inp` 的填写方法

先在“测试剧本”页面选中 `modify_inp`，再在“检索输入卡变量”区域检索记录、说明、卡号或当前值。点击检索结果后，系统只把变量定位写入“变量定位”字段；“新值（修改后）”必须由用户单独填写，选择变量不会覆盖它。检索结果中的“当前值”只用于核对，不能直接等同于新值；若两者相同，该步骤实际上不会产生修改。

输入卡支持自动识别 RELAP5 卡格式和“位置型值 + 说明”格式，也可在“输入卡”页显式选择格式。

RELAP5 变量定位格式：

```text
卡号:卡标识:字段序号@源行号
```

示例：

```text
100:new:2@5
1000101:-:1@10
```

第一条表示第 5 行的卡 `100`，文本卡标识为 `new`，修改该卡的第 2 个字段。第二条表示第 10 行的纯数值卡 `1000101`，修改第 1 个字段；这类卡没有文本关键字，卡标识固定写 `-`，不能写字段当前值。`1000101` 的字段顺序为 **流通面积、长度、体积**，依次对应第 1、2、3 个字段。

位置型值 + 说明格式的定位为：

```text
L行号:字段序号@行号
```

例如 `inputs/CheckSGInput.txt`：

```text
L2:2@2
L3:1@3
```

`L2:2@2` 表示第 2 行的第 2 个字段。这种格式从第 19 列开始识别参数说明；说明中的 `!`、`#` 按普通文本保留。

剧本示例（B-H 列）：

```text
运行目录          action       object       参数1             参数2
TEST-R501         modify_inp   input.txt    100:new:2@5       stdy-st
```

- 字段序号从 1 开始。
- `@` 后是输入卡源文件中的实际行号，不是卡片顺序号。
- 推荐始终通过界面检索并点击字段，不要手工猜测定位。
- 执行时会重新解析输入卡，核对记录/卡号、字段序号和源行号，并只替换该字段的字符区间。
- 修改后字段数、物理行数、行宽、说明列、其他字段、换行和编码都必须保持不变。
- 数值字段只能写入数值；新值过长、无法在说明列之前写入时步骤失败。
- 目标不存在，或定位与当前输入卡不一致时，该步骤直接失败，不会把变量追加到文件末尾。
- 写回前会检查文件是否在修改期间被其他进程改变；发生变化时取消写回。
- 旧式文本文件仍可使用 `变量名: 新值` 的兼容定位，但目标必须已存在且唯一；RELAP5 输入卡应使用上述完整定位格式。

## 4. 结果判断

- `check_output` 的“结果关键字”可填写 `p@控制体编号`、`tempf@控制体编号` 等 RELAP5 变量写法，也可填写带一个捕获组的正则表达式。
- 非 RELAP5 输出应尽量提供 `key: value` 行；预留软件类型尚未实现，不能用 `check_output` 绕过适配器状态。
- 数值比较容差为 `max(1e-6, 1e-4 × |期望值|)`。
- 任一步骤返回失败时，该用例停止执行并标记为不通过/中断。
